# 每日出稿失败补位

## 需求与范围

## 行为约定

- 生成明确失败、文章缺标题/正文、审核低分或审核结果无效，均保留原创作记录并换下一候选，不计入当天名额。
- 草稿明确失败时继续下一候选；推送请求异常或轮询超时不能假定失败，应保留创作及草稿 ID，查询实际状态，避免重复推送。
- 同一公众号每天的成功结果和未完成创作持久化；重启或当天重跑先恢复原任务，已满足名额的号跳过。
- 当前快照内候选去重、顺序消费；无更多候选或跨日时停止，不以递归无限重试。接口不可用时保留进度并明确报告，其他公众号可继续。
- 运行采用进程锁，防止同时启动多个自动脚本。成功从服务器草稿记录回读核实，不能只依赖本地计数。
- 草稿 API 当前不返回 source_creation_id。通过服务器已有 sudo/docker 权限，在 API 容器内执行按账号、日期、创作 ID 参数化的只读查询，精确核实成功数量和推送归属，不按标题猜测。进度文件按账号和模拟/实推模式分开，原子保存于现有 state 目录。
- 素材搜索看过但未选中的主题留在候选队列，只将最终选中的主题记入历史，避免一次搜索消耗多篇尚未尝试创作的候选。
- 原有 no_sources 放行策略、score>=80 门槛、素材搜索优先策略保持；不会群发，不自动改 AI 模型参数。

## 风险与缓解

- 草稿推送超时或响应丢失时，微信可能已接收。先查询该创作对应草稿；仍不能确定时保留待核实状态，停止该号本次补位，防止重复。
- 审核服务整体不可用或持续失败时，反复换篇可能消耗费用。有限候选和自然日作为停止边界；接口异常暂停当前号并保留状态，日志不把未完成算成功。
- 脚本部署时服务器可能有新改动。先比对源文件 SHA256、备份，再替换单个脚本并语法验证；保持现有调度入口。

## 验收

- 多次生成失败后成功，只产出目标数量。
- 审核低分、无效审核、空标题/正文均继续下一篇。
- 明确推送失败继续；超时或响应丢失先回查，不重复提交。
- 候选耗尽、跨日停止，失败不计成功。
- 同日重跑、进程重启、两个公众号及模拟运行互不错误占用名额。
- 并发启动受锁保护；接口异常不让其他号丢失机会。
